# MapleStoryAnalyzer

*[English README](README.en.md)*

即時追蹤楓之谷遊戲視窗中的 HP、MP、經驗值與等級。透過 OCR（光學文字辨識）直接讀取畫面上的數值，不打字、不用巨集，也不存取遊戲檔案或記憶體。用它來看看每次練功消耗了多少 EXP/HP/MP、比較不同時段的效率，並取得大略的升級預估時間。

只會「看」你的畫面，絕不會點擊、輸入或對遊戲送出任何操作。

▶️ **[示範影片](https://youtu.be/Joqzcg6g798)** — 實際執行時的操作與畫面。

## 功能

- **即時追蹤** — LV/HP/MP/EXP 約每秒更新兩次，每項都有進度條。狀態標籤會顯
  示「校準中」「追蹤中」「閒置」「已暫停」或「已停止」，倒數標籤則顯示目前紀
  錄區間還剩多少時間。**開啟程式後預設是「已停止」，不會自動開始記錄** —
  按 **開始** 才會啟動一段新的紀錄；剛開始的一兩秒會顯示「校準中」，先確認讀
  到的最大 HP/MP 與目前經驗值正確，才開始計算變化量。
- **暫停／繼續** — 隨時可以暫停目前的紀錄。暫停期間畫面仍會持續讀取最新數
  值，但不會計入經驗值變化或 HP/MP 損失，計時器也會停止倒數；按繼續會從暫停
  前的進度接著記錄，暫停期間發生的變化不會被算進去。
- **紀錄區間（session）** — 數值會依計時器自動重置（預設 10 分鐘，可調整），
  所以「經驗值變化」永遠代表「從這段紀錄開始到現在」的變化。時間到時預設會自
  動停止並存入歷史紀錄（可在設定關閉，改成自動接著開始下一段）。隨時可以按
  **重新開始** 提前結束目前的區間，預設會存入歷史紀錄（可在設定關閉）。
- **歷史紀錄** — 每段結束的紀錄都會變成一張卡片，顯示開始→結束時間、經驗值
  增加量（含百分比）、HP/MP 損失（僅供參考，詳見「疑難排解」）。最新的紀錄永
  遠排在最上面。點卡片標題可以自訂名稱（例如「魔法森林」），點卡片右上角的
  「×」可以刪除該筆紀錄。
- **設定**：
  - **視窗縮放** — 用 +/− 按鈕縮放整個視窗。
  - **永遠置頂** — 切換 HUD 是否要蓋在遊戲畫面上方。
  - **語言** — 隨時切換中文／英文，即時生效。
  - **紀錄區間** — 每段紀錄多久自動重置一次（1–60 分鐘）。
  - **計時結束時自動停止** — 預設開啟；關閉後計時結束會直接開始下一段，不
    會停下來（回到舊版的行為）。
  - **重新開始時儲存至紀錄** — 預設開啟；關閉後按重新開始只會捨棄目前進
    度，不會留下紀錄。
  - **顯示項目** — 個別開關 HP、MP、經驗值、經驗值百分比、升級預估時間、預
    估本次經驗值的顯示。
- **升級預估時間** — 紀錄區間累積幾秒資料後，會依目前的經驗值成長速率估算距
  離下一級還要多久。
- **預估本次經驗值** — 依目前速率推估「照這個速度，這整段紀錄結束時大概會拿
  到多少經驗值」。
- **楓幣追蹤** — （設定 → 楓幣追蹤）開啟後，程式會從道具欄的金色楓幣數字讀取
  餘額。開始記錄後先開一次道具欄（I）作為起始值，記錄結束前再開一次作為結束
  值，兩者相減就是這段時間的楓幣變化（買水買裝會顯示為負數）。即時分頁與紀錄
  卡片都會顯示楓幣變化。開道具欄會暫時遮住狀態列，這是正常現象。
- **效率（EXP/分）** — 紀錄卡片上會顯示這段時間每分鐘獲得多少經驗值，方便比
  較不同練功點或時段的效率。
- **被遮擋時仍繼續讀取** — （設定 → 被其他視窗遮擋時仍繼續讀取）預設關閉。
  開啟後程式不再檢查狀態列有沒有被其他視窗蓋住，直接讀取遮擋處的畫面。搭配放
  大鏡類工具（如 Megapipe）使用可能有效，但真的被擋住時可能讀到錯誤數值。

## 系統需求

- **Windows** — 螢幕擷取需要執行中的 Windows 桌面環境，在 macOS/Linux 上無法
  實際運作。
- 安裝好並執行中的楓之谷。
- **遊戲解析度：建議 1366×768 以上。** 實測 1366×768 與 1920×1080 都可正常讀
  取。視窗越大文字越清楚，辨識也越穩定；視窗太小時比較容易讀錯。

## 安裝

不需要 Python，也不需要任何安裝步驟 — 只要 `MapleStoryAnalyzer` 資料夾裡的
`MapleStoryAnalyzer.exe` 就夠了。整個資料夾可以放到任何地方（例如
`Desktop\MapleStoryAnalyzer`），但請保持資料夾完整，因為執行檔需要旁邊的其他
檔案才能運作。

## 使用教學

1. 確認楓之谷正在執行、視窗可見（啟動 HUD *之前* 不必是焦點視窗，但追蹤期間
   需要保持焦點，詳見「疑難排解」）。
2. 雙擊 `MapleStoryAnalyzer.exe`。由於這個執行檔沒有數位簽章，Windows 可能會
   跳出 SmartScreen 警告，請點 **更多資訊 → 仍要執行**。
3. 會開啟一個標題為「MapleStoryAnalyzer」的小視窗，永遠置頂，預設停在 **即時**
   分頁。只要找到遊戲視窗且它是焦點視窗，LV/HP/MP/EXP 就會在一兩秒內開始顯示
   數值。
4. 點回遊戲正常遊玩即可，HUD 會在背景持續讀取。隨時可以切到 **紀錄** 分頁查
   看過去的紀錄，或到 **設定** 分頁調整縮放、語言、紀錄區間長度等等。
5. 用完後像一般視窗一樣關掉即可，不需要額外的收尾動作。

## 改用 Python 執行

- **Python 3.10**（透過 `py` 啟動器，例如 `py -3.10`）。
- 安裝好並執行中的楓之谷（同上）。

在專案資料夾開啟終端機，執行一次：

```powershell
py -3.10 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python .venv\Scripts\pywin32_postinstall.py -install
```

這會建立 `.venv` 資料夾，裡面包含程式所需的一切（OCR 引擎、UI 函式庫、螢幕擷
取函式庫）。只需要做一次，之後用這個指令啟動：

```powershell
.venv\Scripts\python scripts\run_overlay.py
```

不論用 .exe 還是這個指令啟動，程式行為完全相同，上面的使用教學與下面的疑難排
解都同樣適用。

## 疑難排解

- **所有欄位都顯示 `--` 或空白。** 遊戲視窗不是焦點視窗。這是硬性限制，不是
  bug：遊戲本身在失去焦點時會降低畫面更新，導致 OCR 讀不到文字。點回遊戲視窗
  即可。
- **狀態標籤顯示「找不到遊戲視窗」。** HUD 預設尋找標題包含 `新楓之谷` 的視
  窗；如果你的遊戲客戶端視窗標題不同，就會找不到。
- **狀態標籤顯示「狀態列被其他視窗遮擋」。** 有其他視窗蓋在遊戲左下角的
  LV/HP/MP/EXP 那一條上面。程式是直接從螢幕上讀取那塊區域，所以蓋在上面的東西
  會被當成你的數值讀進去 — 遇到這種情況它會暫停等待，而不是記錄錯誤的數字。把
  那個視窗（或 HUD 本身）移開，過一兩秒就會自動恢復追蹤。倒數計時器在被遮擋
  期間仍會繼續走，時間到了也還是會照常結束並存入歷史紀錄 — 不會因為讀不到畫
  面就停在原地不動。
- **狀態列被工作列蓋住。** 遊戲最大化時，畫面最下方的狀態列可能剛好被 Windows
  工作列擋住。請把遊戲改成視窗模式，或把工作列設成自動隱藏。
- **狀態標籤顯示「遊戲視窗已最小化」。** 請還原遊戲視窗（開始追蹤後不必是最
  上層的焦點視窗，但不能是最小化狀態）。
- **某個欄位偶爾讀錯一次，之後又自己恢復。** OCR 偶爾會誤判，通常是戰鬥特效
  或飄血數字剛好蓋住某一幀的狀態列文字。HUD 會沿用該欄位上次讀到的正確數值，
  而不是直接顯示空白，所以單次誤判通常不會被察覺。
- **HP/MP 損失看起來太多、太少，或根本不對。** HP/MP 損失請當成大概的數字，
  不是精確統計。原因有兩個。*取樣頻率*：程式每秒讀兩次狀態列，把前後兩次讀
  數之間的下降量累加起來，所以在同一個 500 毫秒間隔內被扣血又補回來的部分完
  全不會被看到，而同一個間隔內挨的好幾下也只會算成一次。*OCR 誤判*：HP/MP 損
  失是累加值，只要有一次讀錯數字（例如 824 讀成 24），就會灌進一筆很大的假損
  失，而且會一直留在這段紀錄裡。經驗值沒有這個問題 — 它只取「結束減開始」，
  中間讀錯一次下一輪就會自己修正回來。如果某段紀錄的 HP/MP 數字明顯離譜，按
  **重新開始** 讓它重新計算即可。
- **數字看起來卡住不動，明明在玩但經驗值沒變。** 先看狀態標籤：如果顯示「追
  蹤中」，代表資料正常更新；如果 HP/MP/EXP 真的都沒變化，那就是真的處於閒置
  狀態，不是 bug。如果標籤顯示錯誤訊息，請參考上面兩點。
- **文字太小、太擠，或視窗大小很奇怪。** 到「設定」→「視窗縮放」，用 +/− 按
  鈕調整。縮放到很小時如果選項被裁切，「設定」分頁也有捲軸可以捲動。
- **不想讓它蓋住遊戲畫面。** 到「設定」關掉「永遠置頂」，或像一般視窗一樣移
  動、縮放它。
- **經驗值偶爾會停住一兩秒才跳動。** 這是正常的：程式會檢查每次讀到的數字是否
  合理，讀錯的那一幀會被丟掉、沿用上一次的數值，等下一幀讀對了再更新。與其顯示
  錯誤的數字，不如慢個半秒。
- **快速連按兩次「重新開始」後，數字看起來怪怪的。** 這是設計行為：1 秒內的
  重複重置會被忽略（避免產生時長為 0 的無意義紀錄），不是 bug。
